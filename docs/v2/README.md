# Kizuri Engine v2

## PT-BR

### Visao

`Kizuri Engine v2` e a nova geracao da engine. A `v1` permanece como legado e referencia historica, enquanto a `v2` nasce como produto proprietario de longo prazo para jogos `2D` e `3D` completos.

### Objetivos oficiais

- Entregar uma base profissional para jogos comerciais, nao apenas prototipos.
- Suportar `2D`, `3D`, scripting em `C#`, editor premium e pipeline de assets serio.
- Escalar bem em `PCs modestos modernos` sem abrir mao de recursos visuais avancados.
- Nascer com arquitetura preparada para `world streaming`, modularidade e crescimento sustentavel.
- Publicar documentacao bilíngue desde o dia zero.

### Principios

- `Performance first`: cada subsistema precisa ter estrategia clara de escalabilidade.
- `Tooling first`: editor e pipeline sao parte central do produto, nao acessorios.
- `Data-driven`: assets, cenas, materiais e build devem ser orientados por dados e metadados.
- `Interop limpa`: `C++` no nucleo, `C#` para scripting e extensoes de alto nivel.
- `Build reprodutivel`: tudo precisa compilar por workflow no `GitHub`.

### Documentos iniciais

- `ARCHITECTURE.md`: arquitetura macro, modulos e limites de responsabilidade.
- `ROADMAP.md`: marcos de entrega da fundacao ate a primeira release publica forte.
- `SCRIPTING_CSHARP.md`: modelo oficial do sistema de scripts.
- `GETTING_STARTED.md`: guia inicial para usuarios e contribuidores tecnicos.

## EN

### Vision

`Kizuri Engine v2` is the next-generation engine line. `v1` stays as a legacy and historical reference, while `v2` is built as a long-term proprietary product for complete `2D` and `3D` game development.

### Official goals

- Deliver a professional foundation for commercial games, not only prototypes.
- Support `2D`, `3D`, `C#` scripting, a premium editor, and a serious asset pipeline.
- Scale well on `modern modest PCs` without giving up advanced visual features.
- Start with architecture ready for `world streaming`, modularity, and sustainable growth.
- Publish bilingual documentation from day zero.

### Principles

- `Performance first`: every subsystem needs a clear scalability strategy.
- `Tooling first`: editor and pipeline are core product features, not accessories.
- `Data-driven`: assets, scenes, materials, and builds must be guided by data and metadata.
- `Clean interop`: `C++` in the core, `C#` for scripting and high-level extensions.
- `Reproducible builds`: everything must compile through `GitHub` workflows.

### Initial documents

- `ARCHITECTURE.md`: macro architecture, modules, and responsibility boundaries.
- `ROADMAP.md`: delivery milestones from foundation to the first strong public release.
- `SCRIPTING_CSHARP.md`: official scripting model.
- `GETTING_STARTED.md`: initial guide for users and technical contributors.
